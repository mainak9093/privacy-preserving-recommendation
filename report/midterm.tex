\section*{Project status}

\textbf{OblivRec} composes the two systems the instructor pointed us to:
\textsc{Nudge}'s three-server private matrix factorisation with
\textsc{Pirsona}'s DPF-based private retrieval. The composition is the
contribution --- \textsc{Nudge}'s own non-goals state that it \emph{``relies on
other means \ldots\ to let users fetch data items in a private way''}, while
\textsc{Pirsona}'s training core is superseded, so each paper leaves open
precisely what the other supplies.

Since the survey we have built and verified the \textbf{serving and delivery
half (S1)} end to end on MovieLens-100K, against a model factorised in the
clear. \texttt{demo -{}-user 42 -{}-k 10} splits a user's embedding across three
servers, scores all 1682 items locally on each, lets the user reconstruct and
select the top ten, then fetches each recommended record by two-server DPF-PIR:
ten real film titles, each verified byte-exact against a cleartext lookup and
matching an independent Python oracle position for position. Private
\emph{training} (S2) starts now and is due for the final report; no claim is
made about it here.

The strongest result is a measurement neither base paper reports. Because
\textsc{Nudge} publishes the item embedding matrix in the clear \emph{by
design}, an observed fetch is not one bit of information but a projection onto
a known basis: \textbf{ten observed fetches recover a user's private embedding
to $\cos = 0.84$ and predict 56\% of their next twenty recommendations}. That
is the quantitative reason the delivery layer must be private at all.

\subsection*{Mainak Sarkar (230619) --- W1, FSS core and delivery}

Wrote the implementation and all report material to date; every commit in the
repository is evidence for this section.

\begin{itemize}\itemsep0.1em \parskip0pt
  \item \textbf{Distributed point function} (Boyle--Gilboa--Ishai), written
    rather than imported, templated on the ring from the first commit. Verified
    \emph{exhaustively}: every $\alpha$ against every $x$ to 16 domain bits at
    $b{=}64$ and 15 at $b{=}128$ --- $\mathbf{7.16\times10^{9}}$ leaf checks in
    27 minutes. Keys are \textbf{227\,B} at the demo's operating point against
    16\,KB for a naive query.
  \item \textbf{Found and fixed a real security bug} in key generation: it
    seeded a Mersenne Twister and used the output as DPF seed material. The
    seeds \emph{are} the secret and MT19937 is reconstructible from 624
    outputs, so an adversary with enough key material could rebuild the GGM
    tree and recover~$\alpha$; seed entropy was also $\sim$64 bits against a
    claimed $\lambda{=}128$. Replaced with the OS CSPRNG, abort-on-failure.
  \item \textbf{Catalogue and DPF-PIR read layer.} Fixed-width 256\,B records
    with explicit length prefixes (nine titles carry Latin-1 bytes, so any
    delimiter risks colliding with content). A server answer is one
    \texttt{EvalFull} plus an unconditional inner product --- no
    data-dependent branch, and no data \emph{pattern} either, since every
    expanded coefficient is a pseudorandom share.
  \item \textbf{Serving under secret sharing.} 2-of-3 replicated shares, with
    $\mathbf{a}\cdot\itemembed$ computed locally per server --- no
    communication and no multiplication protocol, because $\itemembed$ is
    public. All \textbf{1682 scores match the Python oracle bit for bit}.
  \item \textbf{The leakage analysis} above, with a \emph{popularity control}
    so the result cannot be an artefact of popular items sitting near
    everyone's top: the identical estimator run on globally-popular items
    reaches only 0.26--0.53, and the attack's margin over it is a stable
    $+0.39$ to $+0.42$ at every $j$.
  \item \textbf{Cost accounting (B1/B5 baselines) and the threat model.}
    DPF-PIR sends \textbf{446$\times$ fewer bytes} than downloading the
    catalogue, but is the \emph{slowest} of the three in server CPU; the report
    states the crossover (8.0\,Gbit/s) rather than showing only the flattering
    panel. Threat model in \texttt{docs/threat-model.md}.
  \item \textbf{Four real bugs found by tests rather than by inspection},
    including a Python/C++ rounding-mode disagreement at every half-quantum,
    and a quantise-then-multiply error that shifted 1650 of 1682 reference
    scores by an amount \emph{any tolerance-based check would have accepted}.
  \item \textbf{Verification infrastructure:} 9 test binaries green in 1.8\,s
    and clean under UBSan trap mode, \texttt{\_GLIBCXX\_DEBUG} and a
    bounds-checked \texttt{Span}; a JSONL benchmark harness; and
    \texttt{make figures}, so no figure is ever hand-edited.
  \item \textbf{Report material:} all 11 sections of the survey, the
    bibliography (66 DBLP-verified entries), and the 17-page technical report.
\end{itemize}
